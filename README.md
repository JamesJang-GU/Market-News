# Market-News: 물류·경제 일일 뉴스 브리핑 자동화

매일 국내 뉴스를 수집해 **SCM/물류 기사 5건**과 **경제 기사 5건**을 골라, AI 요약·시사점과 함께 Notion 데이터베이스에 자동으로 올리는 파이프라인입니다.

```
GitHub Actions (매일 KST 23:30 자동 실행)
   │
   ├─ ① 노션 DB 점검 + 최근 30일 기사 목록 로드 (중복 방지용)
   │
   ├─ ② 물류 5건
   │     Google News RSS (8개 분야) → 원문 본문 수집 → 사내 AI 선별·요약 → 노션 저장
   │
   └─ ③ 경제 5건
         Google News '비즈니스' 주요뉴스 + 거시경제 키워드 6종
         → 같은 사건 묶기 → AI 영향도 평가 → 종합점수 순위 → 노션 저장
```

- 사람이 할 일은 없습니다. 실행이 실패하면 GitHub Actions에 빨간불(❌)이 켜집니다.
- AI가 응답하지 않아도 규칙 기반으로 선별해 업로드는 계속됩니다.

## 1. 물류 기사 선정 방식

### 1-1. 수집

8개 분야별로 Google News 검색 RSS를 사용합니다. 검색 결과는 한국어·한국 지역 기준이고, 기간이 제한되어 있습니다.

| 분야 | 검색어 (요약) | 후보 수 | 최대 기사 나이 |
|---|---|---|---|
| 해상 | 해운, 항만, 해상운임, 컨테이너선, SCFI, HMM + 해운 전문지(KSG 등) | 5 | 48시간 |
| 항공 | 항공화물, 항공물류, 화물기, 항공운임 | 3 | 36시간 |
| 육상 | 화물차, 화물운송, 화물연대, 택배물류 | 3 | 36시간 |
| 철도 | 철도물류, 화물열차, TSR, 중국횡단철도 | 3 | 72시간 |
| 창고 | 물류창고, 풀필먼트, 물류센터 | 3 | 36시간 |
| 글로벌 공급망 | 공급망 + 관세/수출/수입/리스크 | 3 | 36시간 |
| 친환경&기술 | 물류 + 친환경/자율주행/로봇/AI | 3 | 36시간 |
| 규제&정책 | 물류 + 정책/규제/국토부/해수부/관세청 | 3 | 36시간 |

- 분야마다 최신순으로 정렬한 뒤 후보를 뽑습니다. 하루 후보는 약 26건입니다.
- 최근 30일 안에 노션에 올린 기사(URL 또는 제목이 같은 것)는 제외합니다.
- Google News 링크는 `googlenewsdecoder`로 언론사 원문 주소로 바꾼 뒤 본문을 수집합니다. 바꾸지 못하면 RSS 요약문으로 대신합니다.

### 1-2. AI 선별

사내 AI 게이트웨이에 후보 전체를 보내 **5건을 고르게** 합니다.

- **조건**: 해상 기사 1~3건, 나머지는 물류 실무 영향이 큰 순서로 채웁니다.
- **AI가 작성하는 것**: 분류(8개 분야 중 1개), 요약 1문장, 시사점 1문장, 핵심 하이라이트 3개. 모두 명사형 어미로 씁니다.
- **코드가 강제하는 것**
  - 해상이 3건을 넘으면 초과분을 제외합니다.
  - 해상이 0건이면 해상 후보 1건을 따로 분석해서 넣습니다.
  - AI가 5건 미만을 고르면, 고르지 않은 후보 중에서 분야가 겹치지 않게 돌아가며 채웁니다.

### 1-3. AI가 실패하면

AI 호출이 모두 실패하거나 응답을 읽을 수 없으면, 분야를 돌아가며 최신 기사를 1건씩 골라 5건을 채웁니다(해상 우선). 이때 요약은 본문 첫 문장이고, 시사점은 "AI 분석 미수행 – 원문 확인 필요"로 표시됩니다.

## 2. 경제 기사 선정 방식

목표는 아무 경제 기사가 아니라 **경제에 영향이 크고 많이 다뤄진 기사**입니다.

### 2-1. 수집

| 출처 | 내용 |
|---|---|
| Google News '비즈니스' 주요뉴스 | 구글이 중요도 순으로 정렬한 약 70건. 기사마다 다른 언론사의 관련 보도가 묶여 있음 |
| 거시경제 키워드 검색 6종 | ① 금리·한국은행·연준·환율 ② 코스피·증시·주가·나스닥 ③ 수출·무역수지·관세·통상 ④ 물가·유가·경기·성장률 ⑤ 부동산·집값·가계부채·대출 ⑥ 기재부·재정·세제·금융위·공정위 |

하루 약 800~900건이 모이며, 최근 36시간 이내 기사만 사용합니다.

### 2-2. 같은 사건 묶기 → 화제성 측정

- 제목이 비슷한 기사(제목을 두 글자씩 잘라 겹치는 비율이 45% 이상)를 하나의 **사건**으로 묶습니다.
- 사건별로 **보도한 언론사 수**를 셉니다. 많은 언론사가 다룰수록 화제성이 높다고 봅니다.

> 실제 조회수는 사용하지 않습니다. 공개적으로 조회수를 받을 수 있는 공식 경로가 없습니다. 네이버 '많이 본 뉴스'는 robots.txt로 자동 수집을 금지하고 있어 쓰지 않습니다. 대신 **보도 언론사 수**와 **구글 주요뉴스 순위**를 화제성 지표로 씁니다.

### 2-3. AI 영향도 평가

사전점수 상위 18개 사건을 AI가 평가합니다.

| 영향도 | 기준 (한국 경제·금융시장·기업 경영 영향) |
|---|---|
| 5 | 금리·환율·증시·유가 급변, 국가 단위 정책·통상 조치, 주요 거시지표 충격 |
| 4 | 업종 전반·주요 지표에 중기적으로 의미 있는 영향 |
| 3 | 참고할 경제 동향 |
| 2 | 영향 제한적 (개별 기업 소식, 지역·행사·홍보성) |
| 1 | 경제와 무관 (연예·가십·사건사고) |

AI는 영향도와 함께 세부분류, 주제, 요약, 시사점, 하이라이트 3개를 작성합니다. 세부분류는 금융·통화 / 증시·투자 / 무역·통상 / 물가·경기 / 부동산 / 정책·재정 / 산업·기업 / 글로벌 경제 중 하나입니다.

### 2-4. 종합점수와 최종 선정

```
종합점수(100점) = 경제 영향도 60점 + 보도량 25점 + 구글 주요뉴스 순위 15점
```

| 항목 | 계산 |
|---|---|
| 경제 영향도 (60) | 영향도 ÷ 5 × 60 |
| 보도량 (25) | 보도 언론사 수 기준. 20곳 이상이면 만점이고, 로그 척도라 처음 몇 곳의 차이가 큼 |
| 주요뉴스 순위 (15) | 구글 비즈니스 주요뉴스 1위 15점부터 30위까지 차등. 31위 이하나 순위 없음은 0점 |

점수가 높은 순서대로 아래 규칙을 지키며 5건을 고릅니다.

1. 영향도 3 이상만 고르고, 5건이 안 되면 영향도 2까지 허용해 보충합니다.
2. 같은 주제는 1건만 고릅니다(예: '젠슨 황 복귀' 관련 기사가 여럿이어도 1건).
3. 세부분류마다 최대 2건까지만 고릅니다(증시 기사만 5건이 되는 것을 막기 위함).
4. 최근 30일 노션 기사, 그리고 당일 물류 후보와 같은 기사는 제외합니다.

AI가 실패하면 제목 키워드(거시 키워드 포함 여부, 행사·지역성 키워드 감점)와 보도량·순위로 영향도를 추정합니다. 노션에는 "(키워드 추정)"으로 표시됩니다.

## 3. 노션 페이지 구조

기사 1건이 DB 1행이 되고, 물류와 경제 기사는 같은 DB에 들어갑니다.

| 속성 | 물류 기사 | 경제 기사 |
|---|---|---|
| 제목 | 원문 제목 (끝의 " - 언론사"는 제거) | 같음 |
| 날짜 | 업로드한 날짜 (KST) | 같음 |
| 분류 | 8개 분야 중 1개 (예: `해상`) | `경제` + 세부분류 (예: `경제`, `증시·투자`) |
| 요약 | AI 요약 1문장 | 같음 |
| URL | 원문 주소 | 같음 |

노션에서 `분류`에 `경제`가 포함된 것으로 필터하면 경제 기사만 따로 볼 수 있습니다.

**상세 페이지 본문**

```
📊 선정 근거 (경제 기사만)
   예: 경제 영향도 5/5 · 관련 보도 18곳 · 구글 비즈니스 주요뉴스 1위 → 종합 99.2점
💡 AI 시사점
📌 핵심 하이라이트 (3개)
───────────
📄 수집된 원문 내용 (앞 1,500자)
```

## 4. 처음 설정하기

이미 운영 중이면 건너뛰어도 됩니다. 토큰이나 DB를 바꿀 때 참고하세요.

### 4-1. 노션 DB 속성

| 속성명 | 타입 | 비고 |
|---|---|---|
| 제목 | 제목(Title) | 이름이 달라도 됨 (자동 감지) |
| 날짜 | 날짜(Date) | 이름 정확히 일치 |
| 분류 | 다중 선택(Multi-select) 권장 | 선택(Select)도 동작하지만, 경제 기사의 세부분류 태그는 빠짐 |
| 요약 | 텍스트(Text) | 이름 정확히 일치 |
| URL | URL | 이름 정확히 일치 |

그 밖의 속성(예: 파일과 미디어)은 있어도 상관없습니다.

### 4-2. 노션 Integration 연결

1. https://www.notion.so/my-integrations 에서 Integration을 만들고 토큰을 복사합니다.
2. 대상 DB를 엽니다 → 우측 상단 `⋯` → `연결(Connections)` → 만든 Integration을 추가합니다.
   - 이 단계를 빠뜨리면 `404 Could not find database` 오류가 납니다.
   - 링크된 DB(다른 DB를 보여주는 뷰)가 아닌 **원본 DB**에 연결해야 합니다.

### 4-3. GitHub Secrets

GitHub 저장소 → `Settings` → `Secrets and variables` → `Actions`에 등록합니다.

| Secret 이름 | 값 |
|---|---|
| `ALPHA_API_KEY` | 사내 AI 게이트웨이 API 키 |
| `NOTION_TOKEN` | 노션 Integration 토큰 |
| `NOTION_PARENT_PAGE_ID` | 노션 **DB ID** (이름에 PAGE가 들어 있지만 값은 DB ID) |

DB ID는 DB 주소 `notion.so/{워크스페이스}/{32자리 ID}?v=...`의 32자리 부분입니다. 주소 전체나 하이픈이 들어간 형태로 넣어도 코드가 자동으로 정리합니다.

## 5. 실행하기

### 5-1. 자동 실행

`.github/workflows/daily_news.yml`에 따라 매일 **UTC 14:30 (KST 23:30)**에 실행됩니다.

- GitHub 사정에 따라 예약 실행이 수십 분에서 몇 시간 늦어질 수 있습니다.
- **공개 저장소는 60일 동안 활동(커밋 등)이 없으면 GitHub가 예약 실행을 자동으로 멈춥니다.** Actions 탭에 경고가 뜨면 `Enable workflow`를 누르세요.
- 실행이 겹치지 않게 설정되어 있습니다. 실행 중에 또 실행하면 앞 실행이 끝난 뒤 시작합니다(노션 중복 업로드 방지).

### 5-2. 수동 실행

GitHub → `Actions` → `Daily Logistics News Briefing` → `Run workflow`

> **한 번만** 누르세요. 실행 중에 다시 누르면 1건만 대기했다가 앞 실행이 끝난 뒤 실행되고, 그 사이에 더 누른 것은 취소됩니다. 대기했던 실행은 앞 실행이 올린 기사를 중복으로 걸러내지만, 그 사이 새 기사가 나왔다면 그만큼 더 올라갑니다.

### 5-3. 로컬 실행 (개발·테스트용)

```bash
pip install -r requirements.txt     # Python 3.11 이상 필요
export ALPHA_API_KEY=...
export NOTION_TOKEN=...
export NOTION_PARENT_PAGE_ID=...
python news_briefing.py
```

> 사내 PC에서는 사내 보안 프록시 때문에 Python이 `CERTIFICATE_VERIFY_FAILED` 오류로 외부 사이트에 접속하지 못할 수 있습니다. 이 경우 GitHub Actions로 실행하세요. 인증서 검증을 끄는 방식은 쓰지 마세요.

## 6. 로그 읽는 법

Actions 실행 → `run-briefing` → `뉴스 브리핑 스크립트 실행` 단계를 열면 로그가 보입니다. 정상 실행의 흐름은 다음과 같습니다.

```
Python 3.12.x / googlenewsdecoder 0.2.x        ← 3.11 이상, 0.2 이상이면 정상
노션 DB 점검: ID 417169…f0f5 (길이 32)
✅ 노션 DB 점검 통과 (분류 타입: multi_select)
노션 기존 기사 로드: URL 44건 / 제목 44건

===== 물류 뉴스 선정 =====
[해상] RSS 182건 → 선정 5 / 오래됨 0 / 중복 1    ← 분야별 수집 결과
...
총 26개 신규 후보 수집 완료. AI 선별 시작.
SUCCESS: [Default] 응답 수신                     ← AI 호출 성공
✅ 노션 등록 성공: [해상] ...  (5줄)
선별 5건(AI 5 / 규칙 0) / 저장 5건 / 실패 0건 / 해상 1건 완료.

===== 경제 뉴스 선정 =====
[경제] 주요뉴스 70건 / 키워드 600건 → 기사 868건
[경제] 사건 628개 (기존/물류 중복 제외 3) → 평가 후보 18개
[경제] AI 평가 18/18건
[경제] 선정 순위:
  1. 99.2점 (영향도 5, 보도 18곳, 주요뉴스 1위, 증시·투자) ...
  ...
✅ 노션 등록 성공: [경제/증시·투자] ...  (5줄)

===== 결과: 물류 5/5건 · 경제 5/5건 저장 =====
원문 URL 복원 40/44건                            ← 절반 이상이면 정상
```

| 확인할 줄 | 정상 기준 | 아니면 |
|---|---|---|
| `Python … / googlenewsdecoder …` | Python 3.11 이상, 디코더 0.2 이상 | 7장 '원문 본문 없음' 참고 |
| `✅ 노션 DB 점검 통과` | 이 줄이 보임 | `❌` 줄 아래 조치 안내를 따름 |
| `SUCCESS: [모델명]` | 물류·경제에서 각각 보임 | `FAIL:` 줄의 응답 코드·본문으로 원인 확인 |
| `선별 5건(AI 5 / 규칙 0)` | AI 수가 5 | 규칙 수가 많으면 AI 응답 문제 |
| `결과: 물류 5/5건 · 경제 5/5건` | 둘 다 5/5 | 0건인 쪽이 있으면 실행이 실패로 표시됨 |
| `원문 URL 복원 N/M건` | N이 M의 절반 이상 | 경고 문구가 함께 출력됨 |

## 7. 문제 해결

| 증상 / 로그 | 원인 | 조치 |
|---|---|---|
| `❌ 환경 변수 누락` | Secret 미등록 또는 이름 오타 | 4-3의 Secret 이름 3개 확인 |
| `❌ 노션 DB 접근 실패 (401)` | 노션 토큰 오류·만료 | `NOTION_TOKEN` 재발급 후 교체 |
| `❌ 노션 DB 접근 실패 (404)` | Integration이 DB에 연결 안 됨, 또는 DB ID 오류 | 4-2 연결 확인. 페이지 ID가 아닌 DB ID인지 확인 |
| `❌ 노션 DB 접근 실패 (400)` | ID 형식 오류, 또는 페이지 ID를 넣음 | DB 주소에서 32자리 DB ID를 다시 복사 |
| `❌ 노션 DB 속성 불일치` | 속성 이름·타입이 다름 | 로그에 나온 속성을 4-1 표대로 수정 |
| `❌ 노션 등록 실패 (400) … is not a property` | 속성 이름 오타 | `날짜/분류/요약/URL` 철자 확인 |
| `FAIL: [모델명] 응답 코드 401/403` | AI 키 만료, 또는 사내 방화벽 차단 | 함께 출력된 본문 확인. 키 문제면 `ALPHA_API_KEY` 교체. 방화벽(Incapsula 등)이면 사내 PC나 self-hosted runner에서 실행 검토 |
| `⚠️ 모든 AI 모델 호출 실패` | AI 게이트웨이 장애 | 업로드는 규칙 기반으로 계속됨. 장기화되면 위 행 참고 |
| `⚠️ AI 응답 파싱 결과 0건` | AI가 정해진 양식과 다르게 답함 | 일시적이면 무시. 반복되면 `build_prompt`의 양식 안내 보강 |
| 원문 본문 없음 (RSS 요약만 저장됨), `원문 URL 복원`이 낮음 | `googlenewsdecoder` 구버전, 또는 구글 측 변경 | ① 로그 첫 줄의 버전 확인(Python 3.11 이상, 디코더 0.2 이상) ② `pip install -U googlenewsdecoder` 최신판 확인 후 `requirements.txt` 갱신 ③ 계속 실패하면 언론사 공식 RSS나 네이버 검색 API(공식)로 원문 링크를 받는 방식 검토 |
| `[분야] RSS 0건 ← ⚠️ Source 점검 필요` | 검색어 결과 없음 또는 구글 RSS 일시 장애 | 하루 이틀 지켜본 뒤, 계속되면 해당 분야 검색어 수정(8-1) |
| `❌ [경제] 후보 0건` | 경제 RSS 수집 실패 | `ECON_TOPIC_FEED` 주소가 살아 있는지 브라우저에서 열어 확인 |
| 같은 기사가 두 번 올라감 | 수동 실행을 동시에 여러 번 함 (예전 설정) | 노션에서 중복 행 삭제. 지금은 동시 실행 방지가 설정되어 있음 |
| 실행이 30분에서 끊김 | 작업 시간 제한(30분) 초과 | 네트워크 지연 가능성. 반복되면 `timeout-minutes` 상향 |
| 예약 실행이 아예 안 됨 | (공개 저장소) 60일간 활동 없음으로 예약 실행 중지 | Actions 탭에서 `Enable workflow` |

## 8. 자주 하는 수정

수정은 GitHub 웹에서 파일을 열고 연필 아이콘(✏️)을 눌러 해도 되고, 커밋하면 다음 실행부터 반영됩니다.

### 8-1. 물류 검색어 추가·변경

`news_briefing.py`의 `RSS_SOURCES`를 고칩니다.

```python
"항공": [gnews_rss("(항공화물 OR 항공물류 OR 화물기 OR 항공운임 OR 새검색어)")],
```

- `OR`로 단어를 추가합니다. 괄호와 따옴표를 지우지 않도록 주의하세요.
- 분야를 새로 만들려면 `ALLOWED_CATEGORIES`, `CATEGORY_MAPPER`에도 추가하고, 노션 `분류` 속성에 같은 이름의 옵션을 만드세요.

### 8-2. 경제 검색어나 점수 비중 변경

```python
ECON_QUERY_FEEDS = [gnews_rss(q) for q in [
    "(금리 OR 기준금리 OR 한국은행 OR 연준 OR 환율)",
    ...                                        # 줄을 추가·수정
]]
ECON_WEIGHTS = {"impact": 60, "coverage": 25, "google_rank": 15}   # 합계 100 권장
```

- 화제성을 더 중시하려면 `coverage`를 올리고 `impact`를 내리세요.
- 영향도 기준을 높이려면 `ECON_MIN_IMPACT = 4`로 바꾸세요. 대신 5건이 안 될 수 있습니다.

### 8-3. 실행 시간 변경

`.github/workflows/daily_news.yml`의 `cron`을 고칩니다. 시각은 **UTC 기준(KST에서 9시간을 뺀 시각)**입니다.

```yaml
- cron: "0 22 * * *"   # UTC 22:00 = 다음날 KST 07:00
```

### 8-4. 경제 기사 끄기 / AI 실패 시 업로드 안 하기

`.github/workflows/daily_news.yml`의 환경변수를 바꿉니다.

```yaml
ECON_ENABLED: "0"          # 경제 기사 끄기 (물류 5건만)
FALLBACK_WITHOUT_AI: "0"   # AI가 실패하면 업로드하지 않고 실패 처리
```

### 8-5. 하루 기사 수 변경

`news_briefing.py`에서 물류는 `TARGET_COUNT = 5`, 경제는 `ECON_COUNT = 5`를 바꿉니다.

## 10. 한계 및 주의사항

- **조회수 미반영**: 실제 조회수는 쓰지 않고, 보도 언론사 수와 구글 주요뉴스 순위로 대신합니다(2-2 참고).
- **원문 수집 의존성**: Google News 링크 변환(`googlenewsdecoder`)은 비공식 방식이라, 구글이 구조를 바꾸면 깨질 수 있습니다. 그래도 업로드는 계속되고, 본문 대신 RSS 요약이 저장됩니다.
- **AI 판단 편차**: 영향도와 선별 결과는 실행할 때마다 조금씩 다를 수 있습니다. 본문이 짧은 기사는 정확도가 떨어집니다.
- **유료·차단 사이트**: 일부 언론사는 본문 추출이 안 될 수 있습니다.
- **본문 길이**: 노션에는 원문 앞 1,500자만 저장합니다.
- **수집 정책 준수**: 네이버 등 robots.txt로 자동 수집을 금지한 사이트는 쓰지 않습니다. 네이버 기사가 필요하면 공식 [네이버 검색 API](https://developers.naver.com/docs/serviceapi/search/news/news.md)를 쓰세요.
- **저작권**: 원문 일부를 노션에 저장하므로 개인·사내 열람용으로만 쓰고 외부에 공유하지 마세요.
- **보안**: 코드에 사내 AI 게이트웨이 주소가 들어 있습니다. **저장소를 비공개(Private)로 운영하세요.** API 키는 반드시 GitHub Secrets에만 보관하고, 코드에 직접 적지 마세요.
